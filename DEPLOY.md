# Deploying nikhilsolomon.com

## Option 0: Static on GitHub Pages (free, no admin panel)

Good for now: same design and content, no server to run. You edit content locally (in the admin or in `src/content.js`), rebuild, push.

1. Create a GitHub repo for this folder (or reuse `nikhilSolomon/Portfolio`) and push it to the `main` branch:
   ```bash
   git add -A && git commit -m "Portfolio site" && git branch -M main
   git remote add origin git@github.com:nikhilSolomon/Portfolio.git   # or a new repo
   git push -u origin main --force                                    # --force only if replacing the old static site
   ```
2. In the repo: **Settings → Pages → Build and deployment → Source: GitHub Actions**. The included workflow publishes `dist/` on every push.
3. Still in **Settings → Pages**, set the custom domain to `nikhilsolomon.com` and tick **Enforce HTTPS** once DNS is verified. The `CNAME` file is generated by the build, so it survives every deploy.
4. DNS stays as it is today if the domain already points at GitHub Pages. If not: `A` records for `@` to `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`, and `CNAME www` to `nikhilsolomon.github.io`.

To update content: edit in the local admin, then `npm run export`, commit the `content/` folder and push. Or edit `src/content.js` directly and push. Netlify and Cloudflare Pages work the same way: build command `npm run build`, publish directory `dist`.

When you want the contact inbox, uploads from a browser and analytics, move to one of the server options below; nothing about the content changes.


The app is a single Node process with a SQLite file and an uploads folder. Anything that can run Node 22+ and keep a folder on disk works. Two good options below, plus DNS.

## Option A: Render (recommended, about 15 minutes)

1. Push this folder to a GitHub repo (private is fine).
2. In Render, choose **New → Blueprint**, pick the repo. It reads `render.yaml` and creates the service with a 1 GB persistent disk at `/var/data`. Persistent disks need the Starter plan (about $7/month); the free tier loses the database on every deploy.
3. In the service's **Environment** tab, fill in the values marked `sync: false`: `CONTACT_TO` (where contact messages should be emailed) and the `SMTP_*` values if you want email. Leave them blank to keep messages in the admin inbox only.
4. Deploy. Open `https://<service>.onrender.com/admin` and set your admin password.
5. Add the custom domain in **Settings → Custom Domains**: add both `nikhilsolomon.com` and `www.nikhilsolomon.com`. Render issues HTTPS certificates automatically once DNS points at it.

### Render alternatives that work the same way
Railway (add a Volume mounted at `/app/data`, set `DATA_DIR=/app/data`) or Fly.io (`fly launch`, then `fly volumes create data`). Both run the Dockerfile as-is.

## Option B: Any VPS with Docker (Hetzner, DigitalOcean, Lightsail)

```bash
git clone <your repo> nikhilsolomon.com && cd nikhilsolomon.com
cp .env.example .env && nano .env      # set SESSION_SECRET, SITE_URL, SMTP if wanted
docker compose up -d --build
```

Put Caddy in front for automatic HTTPS. `/etc/caddy/Caddyfile`:

```
nikhilsolomon.com, www.nikhilsolomon.com {
    reverse_proxy 127.0.0.1:3000
}
```

Then `sudo systemctl reload caddy`. Back up the `./data` folder: it is the whole site.

## DNS for nikhilsolomon.com

Your domain currently points at GitHub Pages via a `CNAME` file in the old repo and is behind Cloudflare. In your DNS provider (Cloudflare if that's where the zone lives):

| Type | Name | Value |
| --- | --- | --- |
| CNAME (or ALIAS/ANAME at the apex) | `@` | the host Render shows you, e.g. `nikhilsolomon-com.onrender.com` |
| CNAME | `www` | same host |

For a VPS use `A` records with the server's IP instead. Remove the old GitHub Pages `A`/`CNAME` records so they don't conflict. If Cloudflare proxying (orange cloud) is on, set SSL/TLS mode to **Full (strict)** so Cloudflare talks HTTPS to the origin.

Once DNS resolves, disable GitHub Pages on the old `Portfolio` repo (Settings → Pages) so it stops answering for the domain.

## Environment variables

| Variable | Required | Notes |
| --- | --- | --- |
| `SESSION_SECRET` | yes in production | Long random string; `openssl rand -hex 32` |
| `SITE_URL` | yes | `https://nikhilsolomon.com`, used in sitemap, canonical and OG URLs |
| `DATA_DIR` | yes | Folder for the DB and uploads, must be on persistent storage |
| `PORT` | no | Defaults to 3000 |
| `CONTACT_TO` | no | Email address for contact notifications (defaults to the site email) |
| `SMTP_HOST/PORT/USER/PASS/FROM` | no | Any SMTP provider: Zoho Mail (smtp.zoho.com:587), Resend, Postmark, Gmail app password |

## Updating content

Everything content-related is done at `/admin`; no redeploy needed. Redeploy only when you change code. The default content in `src/content.js` is used only on first run.

## Backups

The whole site is `DATA_DIR`: `portfolio.db` plus `uploads/`. Copy that folder somewhere periodically. On Render, use the disk snapshot feature or an `scp` from the shell tab.
